# 企业工作台五项优化

## 问题与目标用户
员工需要容易接入能力、沉淀个人方法；管理员需要真实诊断和反馈追溯。
## 可衡量目标
五条现有入口流程实际可操作并有版本和权限证据；不虚报依赖、命中、完成或根因。
## 非目标
不重做Runtime、ACL、RAG、市场、任务系统，不全量回归。
## 当前范围与优先级
- REQ-001（优先级P1）：Immutable GitHub commit import/update, source/license/hash; readonly actual authorized Core dependency probe; missing/incompatible/unverified version-bound states; MCP existing path failure categorization; no scripts/install/network during probe.
- REQ-002（优先级P2）：Admin enterprise permission plus base EDIT and per-document ACL. Real PostgreSQL config/path, document/version/candidates/location, indexed/miss/limit reasons; original permission preserved; no invented vector/rerank; metadata-only audit.
- REQ-003（优先级P3）：Employee real actor-scoped task feedback; authorized admin review/trace true execution resource versions; unknown stays unknown; manual evidenced cause, expected result/checks/status/recheck then close; no transcript/files/credentials copied.
- REQ-004（优先级P4）：Own editable personal method only. Model draft+diff, explicit apply/save existing expectedVersion resource API; scripts/ACL/dependencies/company formal rules protected; existing runtime preferences truly change, original/other employees unchanged.
- REQ-005（优先级P5）：Keep correct existing streaming/persistent reconciliation and tool collapse. Repair only proven duplicate/out-of-order/switch races. Actual waiting_input vs confirmation and partial/interrupted/completed; inline artifacts and resume retained.
- REQ-006（优先级P1）：Integrate typed existing APIs, build affected Web/Host/Admin/Java once, isolated or controlled actual employee/admin E2E five paths + security, preserve 24 old migrations, backup, immutable affected-component release, public version verify, RC1 tag/package unchanged.
## 用户流程
管理员导入检查→诊断知识；员工执行→反馈→管理员处理复核；个人复制→自然语言草稿→差异确认→保存→新会话运行。
## 验收标准
各REQ对应同编号TEST和任务包，五项实际操作集中验收一次。
## 约束
Java为身份/ACL/资源唯一权威；Core仅执行；不运行第三方安装脚本；不复制受商业限制源码。RC1标签/包和生产数据保留。
## 未决问题
当前静态知识检索质量与执行UI是否存在缺陷由真实证据决定；无实际缺陷保留现状。
