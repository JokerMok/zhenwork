# Office evidence and reconciliation

The enterprise Host supplies these actor-scoped tools through the existing office MCP. No new network port, database or resident Core is needed.

- `inspect_workbook` reads the current XLSX structure, merged/title/header/data regions, formulas and print area. Its SHA256 identifies the exact current input.
- `audit_workbook` reads current XML numeric values as Decimal, computes selected non-overlapping ranges, and independently evaluates the actual `totalCell`. Currency defaults to CNY; monetary outputs use two digits and ROUND_HALF_UP. Same-sheet SUM and arithmetic/reference chains are supported. Selecting both a formula and its contributing cells is rejected as a dependency overlap; explicit matched/mismatch/calculated-only status prevents a discrepancy being treated as verification. Inspection offers actual single-column subtotal candidates and omits hidden history data unless requested. Unknown functions, external references, missing totals, text amounts, circular formulas and stale caches never count as a successful audit. The result includes raw exact total, formatted total, detail-cell count and differences. An unambiguous Date/business-date header also produces current worksheet date groups and exact group totals. Explicit groupByColumn/groupFormat supports other row labels. Group count is distinct worksheet labels, not invoice/event count; a different event-sheet row count cannot invalidate summary dates without original evidence. Unsupported automatic date labels leave date grouping unavailable without invalidating amount arithmetic. Display-rounding differences across groups are explicit. This read-only calculation does not rewrite Excel formula caches or claim full Excel engine compatibility.
- `summarize_json_data` counts/groups actual JSON collections and sums decimal fields. Nested array fields require explicit flattening. Missing/wrong fields fail instead of quietly producing zero. Source summaries do not replace a current workbook audit.
- `edit_workbook_column` changes one inspected column and explicitly removes its old values above the header. Same-file edits require the inspected SHA256; concurrent changes are rejected inside the versioned write transaction. Other ZIP parts are preserved. The result reports reopened values, merge/print-area changes, and formula/reference warnings. Complex print areas remain unchanged with a warning; this tool does not insert/shuffle physical columns or silently expand business formulas.
- `create_evidence_deliverables` validates one source dataset and generates both DOCX and XLSX using the same table and dataset hash. Original quotes and version/location are inserted by the server. Analysis and missing information are separate columns. Compliance (the default) requires independent requirement references before a conformity status is possible. Research uses purpose=research and reports source-location verification without pretending it is customer acceptance. A call accepts up to 32 total references: 32 source-only findings or 16 source/requirement pairs. Actual source access/version is checked before generation and again before each file write. Each output has its own validation/download status; a missing or failed output means partial completion.

The advertised tool schemas are checked before side effects. Legacy Core scalar strings are normalized only for unambiguous boolean/integer fields. Errors identify the offending field. An identical invalid call is limited to three attempts per five minutes; the Core's existing bounded failure recovery remains active. Empty arguments or endlessly repeating an expired quote reference are not recovery.

Wide whitespace separating PDF columns produces separate contiguous quote options. This improves excerpt selection; it does not repair OCR mistakes or establish whether an inference follows from a quote. Every business finding still requires review of units, ranges, qualifying conditions, dates and versions. Supplier claims and labelled regression examples are not independent customer acceptance.

Validation boundary: focused tool tests cover Decimal calculations, current formula evaluation, stale/missing caches, varying rows/decimals, safe edits, untouched parts, quote boundaries, schemas and bounded correction. Business acceptance additionally requires the actual employee web flow, real downloaded artifacts, review of their content, continuation/history and identity checks. Refer to PROJECT.md for the release-specific results; a build or HTTP success alone is never a business pass.

The managed toll-summary skill writes one reimbursement row per evidenced business day. A multi-day PDF is not one dated outing: its per-day amounts retain the same source and unique invoice/attachment registers. Missing parking evidence stays blank. The project parser source and the separately published complete Skill package must be versioned together in the maintenance record. Date columns cannot be audited as currency amounts.
