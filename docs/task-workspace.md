# 持久任务工作区

员工从原聊天发送工作；同一会话的补充和修改是新轮次，重试只针对未完成部分。现有任务页及会话状态提供排队、运行、补充、确认、成果、取消及中断恢复入口；旧会话没有证据的状态保留未知。任务状态与环境准备分开。补充日期等简短资料会继承未完成交付；已经核验的成果沿用固定版本。需改变范围时，在任务续作区勾选“用本次要求替换未完成交付”，保留已有成功成果。

## 执行与授权

Host在响应受理前，将执行标识、员工归属、输入、知识范围和轮次持久化到 `shared/profiles/control/<serverHash>/<userId>/tasks/tasks.json`；实际路径由现有 `enterpriseManagedResourcePath` 解析。文件700/600、fsync和原子替换，仅Host可读。相同稳定request_id与相同有效载荷复用同一次尝试，变化请求不能占用旧标识。状态订阅和浏览列表不启动或续期Core。

后台授权使用现有RC2 `ai_background_grant`，job命名空间为task_，Host秘密保存在独立task-grants.json；不保存浏览器Cookie充当后台身份。派发、工具、模型、知识和结果返回复核当前员工及资源权限，任务权限不扩大助手/知识/外部连接授权。

沿用单Core、启动并发1、Core启动队列2/等待180秒，业务队列预算2、最长30分钟；真实执行预算20分钟。排队满明确拒绝，已受理的启动等待不会被静默丢弃。无额外Core池或普通聊天cron。空闲仍120秒和既有安全检查，真实工具/子进程/写入期间不回收。等待补充或确认保存问题后停止原生轮次并释放授权，Core按既有安全策略回收；继续时重新授权和按需启动。

Office工具保存真实步骤与成果回执；实际原生轮次空闲后，重新校验当前文件结构、SHA、要求格式、失败步骤和实际回复。模型声明、流结束、HTTP200不能单独判完成。未完成交付显示部分完成，已核验成果在重试时受保护，不能重复覆盖。普通问答无需建立计划。

## 恢复与维护

服务启动把无法确认结果的已发送执行标为中断待恢复；安全未发送队列可以继续。员工需核对后在原任务继续，不自动重放结果不明的外部写操作。取消保留已生成文件；旧尝试回调不可覆盖后续轮次。办公生成、检查、计算和修改子进程接收请求中断信号并终止；停机先停止派发，取消自己的准备等待并收敛在途回调，再记录中断。确认绑定完整工具参数，不依赖截断说明，无法核实操作范围时禁止批准。历史成果按版本字节验证，不自动重指不同内容的新版本。

本轮无数据库迁移，复用现有23条checksum链。发布只重建员工网页、Host和Java；管理网页、监控、Rust与精确amd64镜像复用。`deploy/tencent/deploy.sh` 自动按输入差异决定管理端和监控产物复用，`build-linux.sh` 核对复用字节摘要。

回滚只退应用与配置，不退数据库、文件或授权。先暂停新受理、等待或显式中断新任务，保留任务文件和task-grants；旧版不会解析独立task授权文件，但没有新任务UI。恢复新版可再次查看任务。遵循现有有审核文件的manage.sh rollback，不能删除持久数据来回滚。
