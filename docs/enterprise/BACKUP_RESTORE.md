# 备份与数据恢复

备份前通知员工维护，等待在途任务结束。正式脚本只停止本实例的入口/Host/控制端，确认无本实例工作容器后，导出 PostgreSQL 并收集配置、密钥、上传、员工独立目录、会话、个人方法、成果和文件版本。每员工的 `runtime/node` 受管程序缓存不进数据备份；恢复后从相同发行组件自动重建。员工工作区中同名目录、上传、个人方法及成果完整保留。备份回执列出缓存排除规则。

数据经 GPG AES-256 加密；临时数据库转储只在 root 私有目录短暂保存。备份密钥不进入归档，必须单独离线保管。恢复后企业模型密钥仍受现有密钥加密机制保护。

```bash
sudo bash deploy/enterprise/backup.sh /root/enterprise.env /secure-backups/enterprise-unique.gpg
```

保存 .gpg 与 .sha256；备份后脚本重启本实例。仅凭备份命令成功不能证明可恢复，须检查恢复回执。

恢复目标必须是全新独立环境，使用备份时相同的绝对安装路径，以及与备份清单匹配的应用包。RC1 不承诺自动迁移员工文件的绝对路径。不得覆盖正在运行的企业。隔离演练可停止环境 A，将整个 A 目录和其数据原样保留，再用空目录、独立服务/容器项目在同一规范路径建立 B；A、B 不能同时运行。正式灾备建议新机器使用同一路径。

```bash
sudo bash deploy/enterprise/restore.sh /root/enterprise.env /secure-backups/enterprise-unique.gpg
```

脚本检查加密文件指纹、归档路径、匹配版本、文件指纹和迁移台账。同一员工的受管会话 Skill 链接转为相对链接恢复；跨员工、越界、重复条目及通过链接写入归档路径均拒绝；恢复到空数据库，重新生成本目标服务配置并启动。备份密钥、配置文件及 TLS 域名应由本企业管理员持有。外部服务端的数据、操作系统和应用二进制不在此数据备份范围，需单独保留相同发行包。Redis 为会话/缓存，恢复后重新登录，不恢复旧浏览器登录态。

恢复后抽查管理员/员工/部门角色、资源和授权、知识元数据、旧会话、上传、结果与版本、个人方法和撤权边界。实际演练状态见 ACCEPTANCE.md。
