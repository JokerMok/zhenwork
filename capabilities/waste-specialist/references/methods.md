# 六类行业方法与复用关系

| 工作 | 上游工作流 | 实际执行与行业边界 |
|---|---|---|
| 台账 | 01清洗、02合并、21异常 | ledger；节点+记录标识去重；同键冲突保留问题；kg/吨按配置换算；分类只用主数据 |
| 库存 | 13库存检查 | inventory；期初+入库-出库+显式调整；内部移库库区一减一增；盘点与账面分列；内部提醒不作法规结论 |
| 清运 | 05对账、06三表、10凭据匹配 | transfer；显式清运号关联一对多；出库/磅单/联单/接收分别统计；跨期接收保留期末状态 |
| 费用 | 05对账、23合同 | settlement；合同原文摘录实读核实，分回收收入与处置支出；元/吨、车次、含税条件；缺项不生成最终金额 |
| 产废分析 | 16月报、20摘要 | 原有DataAnalysis完整计算、已发布WASTE_MONTHLY口径；本包仅提供规范输入，不新造月报算法 |
| 资料准备 | 15完整性、22归档、25制度 | checklist；有效内部要求→目录→实际文件指纹；缺件/目录未列/明确冲突分别表达；不对外申报 |

新适配processor只补上游没有的行业确定性逻辑：通过stdin接收全量受控输入，stdout返回结果，无文件写入/联网/子进程。完整XLSX解析和成果生成复用平台既有实现。平台只接受已审查脚本SHA；配置可自助修改，不能以个人脚本开通任意宿主执行。

示例跨度2026-08和09，跨期接收至10-02，三车间、三个库区、同一组业务号。一般/危废是显式虚构主数据，D-*不是实际国家废物代码。示例包含生产量，但当前口径未配置单位产废，不从缺口资料推断降本/最优。

references/company.json中tables为XLSX表名/字段映射/recordType；JSON规范键与同表定义一致。requiredTables保证缺表会报错。真实适配调整主数据、字段、合同、要求和连接即可，不替换平台程序。固定模拟截止日位于preferences.cutoff，使用其他期间须显式修改保存个人版本或发布企业版本。

上游workflows.json为完整索引，workflows.md及prompts/为可分段加载的方法；员工详情可查看完整JSON，模型可按文件读取。原上游SKILL保留在upstream-skill.md，项目授权与本入口优先于上游冗余审批要求。
