# P2 身份认证与企业权限

单企业实例使用 Better Auth 1.7.5 的密码算法、Cookie、会话、密码变更和注销；业务层负责用户启停、部门、角色、权限、首次改密和管理授权。未开放注册、组织租户或通用 impersonation 接口。浏览器仅收到 HttpOnly Cookie，不收到登录 token JSON。

管理 API 位于 `/api/admin/users`、`departments`、`roles`、`permissions`；写入有严格 schema 与固定 Origin。管理员创建账户后必须首次改密，管理重置后同样必须改密。受控重置使用 Better Auth 的 password hash 实现并原子更新凭据、撤销会话、记录审计，不另造密码协议。当前没有邮件发送服务，因此不开放邮件自助找回入口。

所有调用重新检查服务端会话、业务 enabled 和权限；敏感管理事务在锁定单企业配置行后再查当前会话及权限。部门/角色变化同步递增权限版本并撤销既有会话。内置角色不可修改，低权限管理员不能授予自己没有的权限或修改系统管理员；最后一个启用的系统管理员不能被停用或移除管理员角色。角色删除有成员引用时拒绝。

登录、改密、重置和撤销围绕用户行锁排序，避免旧密码验证与管理员重置交错后创建可用会话。Better Auth 使用独立限额连接池，业务事务不会占满连接池后等待自身认证查询。昂贵密码工作限制为 4 个执行、24 个排队，超出返回 RateLimit。

持久限流记录在 PostgreSQL `auth_attempt_limits`。初始策略为每账户每分钟 5 次登录尝试、每连接源 IP 每分钟 40 次登录和 120 次认证操作。账户和 IP 索引使用 HMAC；不保存明文密码、Cookie 或账号输入。输入转发 IP 不受信任，生产反向代理后的策略与 20 人容量在 P8 验证。限流适用于失败与成功尝试，返回 Retry-After。过期记录按一天清理。

身份事件已接追加审计链；本阶段只验证事件存在、密码/Cookie 不入事件以及数据库拒绝改写。完整链锚点、外部备份和审计 UI 属于 P6/P8。

证据：`evidence/v1/p2/identity-with-race.json`，24 项真实 HTTP/API 正负例，通过。覆盖普通员工、组织管理员、知识管理员、审计员、最后管理员、超范围委派、首次改密、变更后旧 Cookie、禁用、到期、撤销、重置、CSRF、公共注册关闭、限流，以及持有账户锁期间发起的旧密码登录在重置提交后失败。密码并发单元检查另在 `apps/server/tests/auth-bounds.test.ts`。

按用户原始阶段定义，P2 收口为 Auth/RBAC；可信 Runtime Manager/Gateway 随 P3 正式会话链路实现和验证。管理 UI 在 P4 接入这些 API。P2 API 通过不等于完整产品或生产部署通过。
