# P4 管理后台与企业品牌

管理后台独立位于 `/admin`，员工入口仍为 `/`。导航按当前权限呈现，每个服务端管理 API 独立鉴权。管理员没有员工私人会话或文件的内容读取接口。

## 复用

沿用经过官方 cleanup 的 Dashboard 组件、Base UI 表单控件、TanStack Table / Query。新增中文分页与空状态，来源和改动摘要更新于 third-party-lock.json。图片处理直接使用 sharp 0.35.4；应用层为 Apache-2.0，平台 libvips 的 LGPL 分发义务仍归 P8 Release Gate。

## 已实现

- 总览的员工、助手、知识库与当前任务数量，不显示私人任务内容。
- 部门增改与空部门删除；角色权限配置与内置角色保护。
- 用户服务端搜索、分批/表格分页、创建、编辑、部门/角色分配、停用/启用、密码重置和登录撤销。账号新建/重置后需首次改密。
- 助手配置、角色分配、知识库关联、允许能力；模型仅管理当前已部署验证的标识、启用状态与输出上限，不在浏览器提交凭据。
- 已审查能力的全局开关，不能安装任意脚本、技能或 MCP 服务。
- 完整 BrandConfig：产品/企业名称、浅色与深色标志、favicon、颜色、登录标题/说明、支持信息和版权。员工和管理界面每 5 秒刷新；支持浅色/深色外观。
- 系统状态、数据库版本与连接器关闭原因。备份实际工具、知识与审计/用量页面按 P5/P6/P8 接入，未实现项明确展示当前状态。

## 安全边界

品牌更改使用配置版本并发检查；所有 asset ID 必须引用已有品牌文件。图片限定 PNG/JPEG/WebP、256 KB 与总计 1,048,576 像素以内，重新编码 PNG 并剥除元数据；禁止 SVG/HTML 和远程 URL。仅当前品牌引用的文件允许匿名访问，上传后未配置的图片返回 404。资源响应 nosniff 与严格内容策略。

模型与助手变更增加助手版本；旧任务不能使用新策略继续执行，历史仍属于原员工。工具开关每次调用重新验证。单企业配置不包含租户/套餐/账单入口。

## 验证

实际 PostgreSQL/HTTP 的 11 组管理/品牌正负例通过；真实 Chrome 的 8 组管理流程通过。首次改密/禁用退出 3 项、账号撤销后查询缓存隔离 2 项也经真实浏览器验证。认证失败移除私人查询缓存；新账号登录不能短暂复用前账号历史。图片参数类型与表单按钮默认 type 的初始失败记录保留在 evidence/v1/p4。

浏览器使用合成账号、本机入口，不能代替真实多设备远程验收。
